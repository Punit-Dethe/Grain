## Settings-only audio-file transcription

Target: `73c095857bc4eadff097f64767c40ad129cc372d` (#2315), with the
intervening #2326 Windows GradeChip change already assessed as not applicable.
Settings → Application → Storage now owns the only Choose file entry point.
There is no app-wide drop target, History import button, new wizard or harness.
Results appear in existing History; imports never paste into another app and
never request AI post-processing. Existing History retry uses the same queue.

Adopted Handy's Symphonia decoder, Rubato resampling, 16 kHz mono recording,
chunking, database source name, retention exclusion and progress queue. Supported
containers depend on their audio codec: WAV, MP3, FLAC, AAC/M4A, AIFF, Ogg/Vorbis
and supported audio tracks in MP4/MOV. Opus is not advertised/supported.
Files are limited to 60 minutes of decoded audio. One decoder is admitted at a
time; imports receive UUID recording names and partial-write cleanup. Decoder
errors create no History entry. Imported recordings remain until explicitly
deleted, independently of dictation retention settings.

Grain-owned adapters use the existing single resident engine and admission
lease. Background chunks yield to recording/processing; foreground inference
waits for the current chunk rather than failing on its lease. A background
chunk verifies/reloads its pinned Standard model after foreground use. This is
correctness for the current app, not a new multi-model orchestration layer.
**User direction (2 November): move to one selected dictation model later.**
Do not expand coordination of separate model selections; that product change
is outside this upstream import block.

The worker starts lazily and exits when idle. A panic fails only its job; a
thread-start failure reports errors and releases queue holds. Settings listeners
are disposed on unmount, and reopening uses a live queue snapshot. Queue events
are ordered with cancellation/retry admission; cancellation is distinct from
success and takes effect at a chunk boundary. Closing Settings keeps jobs
running. Quitting Grain loses the in-memory queue; unfinished entries can be
retried from History after restart. Jobs are not silently replayed.

Validation: explicit binding export; full backend suite **721 passed, 23 opt-in
ignored**; frontend production build and **102 unit tests passed**. Coverage
includes real stereo WAV decode/resampling and partial tails, invalid input,
sample-rate-independent duration policy, queue target/dedup membership,
foreground/background engine lease handoff, and upstream History schema/latest
completed-entry behavior. The earlier onboarding checkpoint also passed **245
Core tests**. These are automated checks, not native model/UI acceptance.
