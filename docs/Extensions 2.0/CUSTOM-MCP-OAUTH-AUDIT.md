## Implementation and boundaries

The existing `Provider` adapter now borrows the configured record's host-owned account identity. Catalogue providers retain their existing keys. Two configured records with the same endpoint have separate grants; JSON still cannot provide credentials, account keys, enabled state or trust. No new OAuth engine, executor, dependency, persistent client or background service is introduced.

Three guarded Tauri commands connect, inspect status and disconnect a configured account. Each requires the main window, Developer Mode and the exact canonical string revision. Sign-in uses the existing SDK discovery, DCR, resource-bound PKCE exchange, bounded callback listener, timeout, destination policy and OS vault. Successful sign-in enables only its current host account. Explicit enable requires a stored grant; merely importing an OAuth record cannot activate it. Status reports stored/recovery state, not a guarantee that the provider currently accepts the token. No token enters settings, JSON exports, the Agent directory or harness evidence.

The vault adapter carries both the cancellation ticket and the exact metadata lease. Every blocking load/save/delete checks both before accessing the vault. Operation leases remain owned by detached blocking work until it finishes. Revision changes, endpoint changes, removal, disable and developer shutdown invalidate work; the final enablement commit also checks metadata ownership. A duplicate connect refuses without invalidating the first flow. The SDK remains responsible for refresh behavior; Grain retains account isolation, consent, cancellation and storage boundaries.

Endpoint/authentication changes and removal disable and retire the old account before publishing replacement metadata. Retirement attempts all three exact owned keys: grant, client secret and registration. A vault error preserves the old record/identity for an explicit cleanup retry. This is not a distributed transaction: partial vault deletion or a later file-publication failure can leave the preserved record signed out. The command returns an error; it does not claim rollback, silently activate a replacement or retry an uncertain action. Revision exhaustion refuses before retirement. Label edits preserve the account while invalidating old approvals; identical saves preserve current work. Disconnect clears the grant and enablement but retains registration configuration, matching the shared catalogue logout model. This DCR-only slice has no custom client-ID writer.
