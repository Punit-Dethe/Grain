# Store MCP acquisition foundation — 5 October 2026

Branch: `extensions/tool-only-retirement`. E2 remains in progress. This is backend acquisition evidence, not certification of the complete store-MCP feature or a production release.

## Implementation

- Signed catalogue entries explicitly distinguish `artifact_kind: "mcp-descriptor"` from legacy native packages. Missing kind retains native encoding; unknown kinds fail parsing. The native installer refuses descriptor artifacts.
- A descriptor artifact is at most 8 KiB, fetched as `blob/<sha256>.mcp.json`. Its size, hash, ID, version, name and description must match the verified catalogue. MCP entries cannot carry native permissions/host contributions or self-declared unreviewed trust.
- The existing store freshness, revision, cancellation, revocation and HTTP byte limits guard acquisition. Final developer consent and catalogue state are rechecked before atomic publication. No MCP endpoint, OAuth browser, credential or worker is started by acquisition.
- The existing connection registry preserves original descriptor bytes and hash. Store connection/account IDs are generated by the host in a distinct `mcp:v1:store:<extension>:<connection>:<account>` namespace. Restart validates those bytes and their definition; failed saves preserve old state.
- Duplicate store acquisitions and direct JSON edits are refused. Removal uses the same registry/account cleanup path; namespace pruning now derives from the record instead of assuming configured ownership.
- `store_mcp_install` is main-window and Developer Mode gated. Store records remain inactive: connect, enable, runtime execution and Agent directory publication cannot activate them while verified update/revocation integration remains unfinished. The existing native store UI does not display descriptor cards yet.

Stored provenance is a host-profile record, not an independent signature certificate. Acquisition starts from `StoreState`'s verified catalogue; the private admission value only proves artifact/hash/metadata consistency. Publisher JSON cannot construct a trusted host source. No SDK/OAuth replacement or physical legacy removal occurs.
