# Generative UI in the Agent notch (experiment)

Branch: `experiment/openui-notch` (from `main`, 2026-11-15). Experiment only — not for `main` until the user says so.

## Goal

A third notch view, **Canvas**, beside Recall and Chat. Instead of a chat thread, the Agent answers with an interactive UI (weather card, place list, comparison table, steps…) generated by the model in OpenUI Lang and rendered by our own component library. The view replaces the chat wholesale: no message bubbles, only the latest generated UI. The notch shell sizes itself to that UI, within a hard min/max.

## Library choice

[OpenUI](https://github.com/thesysdev/openui) by Thesys (MIT). We use only **`@openuidev/react-lang`** (parser + prompt generator + streaming `Renderer`, ~225 KB with `lang-core`), pinned to **1.0.2** (oldest 1.x old enough to trust; `lang-core` pinned by `overrides`).

Not used:

- `@openuidev/react-ui` — 16 MB unpacked, pulls d3, Radix, KaTeX, react-markdown. Too heavy for a low-RAM notch, and its look is not ours.
- `@openuidev/react-headless` — wants the Vercel `ai` SDK and its own chat state; the host already owns the conversation.

Privacy checks done before installing:

- `lang-core` has a **postinstall** script that sends install telemetry to PostHog. Bun does not run dependency lifecycle scripts (not in `trustedDependencies`), so it never runs.
- Runtime telemetry (system-prompt generation, parser parse) is **opt-in** (`OPENUI_RUNTIME_TELEMETRY_ENABLED`) and in a browser there is no `process.env` to opt in with. Off.
- In dev builds `react-lang` auto-mounts its devtools widget into the page. `canvas/devtoolsOff.ts` sets the library's own opt-out flag before the library is imported.

## Shape

```
Notch (React, agent-notch webview)                  Host (Rust)
──────────────────────────────────                  ───────────
canvas/library.tsx  ── createLibrary(components)
        │  library.prompt(...)  = UI spec string
        ▼
AgentCanvas  ── commands.agentRunCanvas(request, spec, context) ──►  agent_run_canvas
        ▲                                                            ├ loads canvas thread (canvas.json)
        │                                                            ├ build_messages + spec as system msg
        │                                                            ├ run_with_tools (same tools/providers as chat)
        └──────────── AgentReply { text = OpenUI Lang } ◄────────────┴ appends request+reply, saves (no TTS, no chat record)
<Renderer response=text library=…>  →  our notch-styled components
```

- **The host owns the canvas memory** (`agent/canvas.json`: the last N canvas turns). Follow-ups ("…and skiing spots near me?") see the earlier requests and the UIs the model produced. Survives the notch window being destroyed; a reopened Canvas shows the last UI. `agent_canvas` reads it, `agent_canvas_clear` starts fresh.
- **The frontend owns the component library**, so the prompt describing it is generated from the same definitions that render it (single source of truth). It goes to the host as the `spec` argument.
- **Interactions**: buttons emit OpenUI `continue_conversation` → sent as the next canvas request; `open_url` → opened by the host link opener; forms send their field values along.
- **Fallback**: a reply that is not OpenUI Lang (no `root =`) renders as plain markdown, so a misbehaving model never shows a blank canvas.
- **Tool confirmations** keep working: a host-held confirm shows its Confirm/Cancel bar under the canvas.
- **Voice summons**: a summon is a chat, unless the notch was left on Canvas — then the spoken request asks for a UI and the notch reveals into it.
- **Lifetime**: the renderer is mounted only while Canvas shows (switching away unmounts it); the UI program lives on the host, so nothing is lost.
- **Switching**: the header gets a third tab (Recall · Chat · Canvas); Tab / Shift+Tab walks them. "New canvas" (pen icon) starts over.

## Sizing

Live window resizes are off the table (WebView2 re-present blink; tauri#3990 freeze). The notch already opens at a fixed reply size and clips the window with a region to the shell (`agent_notch_shape`), which is how Recall and reminders fit their content. Canvas reuses that:

- The reply window grows from 600×360 to **660×560** CSS px (`NOTCH_REPLY`), the canvas maximum plus clip slack.
- **Chat and the chat list stay 600×360**: they become a fitted shell too (always clipped once revealed), so they look exactly as before.
- **Canvas** measures its content (`ResizeObserver`) and asks for `clamp(360, w, 620) × clamp(140, h, 540)`. Beyond the max it scrolls inside the shell.
- The existing clip rules apply unchanged: widen before growing, tighten only after the shell has settled.

Windows-only clip (as today). On macOS/Linux the transparent window area is not clipped — acceptable for the experiment.

## Components

`Canvas` (root), `Stack`, `Card`, `Heading`, `Text`, `Markdown`, `Badge`, `Icon`, `Image`, `Stat`, `Progress`, `Divider`, `Details`/`Pair`, `Table`, `Steps`, `List`/`ListItem`, `Buttons`/`Button`, `Form`/`Input`/`Select`. No maps: real map tiles need a map library and network tiles; a place list with "Open in Maps" links (`open_url`) covers the example for now.

### Colour (2026-11-15, user: "too dark and monotone")

v1 used only the notch's monochrome tokens and no component had a colour option, so every reply came out grey. Now an optional `tone` (blue, sky, teal, green, amber, orange, red, pink, purple, indigo, slate) on `Canvas`, `Card`, `Heading`, `Icon`, `Stat`, `Badge`, `Progress` and primary `Button`. The `Canvas` tone washes the whole shell in a soft glow from the top (via `:has()` in `canvas.css`); `Stat` trends are green up / red down. A prompt rule maps subjects to tones (weather, money, places, warnings, food) and caps it at one main tone plus two.

### Images

`Image(src, alt?, caption?, shape?)` and a `ListItem` thumbnail. https only, `no-referrer`, and a broken URL hides itself. The prompt allows only image URLs that came back from tool results (the web extension), never invented ones. Loading a remote image tells that host the user's IP — inherent to showing web images.

### Voice line

Each reply starts with one `SAY: …` line: one or two short, warm sentences that give the answer ("It's 14 degrees with light rain until 3, then it clears up."), never a description of the UI. The host splits it off (`split_speech`), speaks it through the normal talk-back (so the "Agent talk-back" setting governs it), and returns only the UI. The memory keeps both so the model keeps the pattern. A summon's Canvas reply opens the notch and speaks (never the compact speaking bar).
