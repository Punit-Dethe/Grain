# Generative UI in the Agent notch (experiment)

Branch: `experiment/openui-notch` (from `main`, 2026-11-15). Experiment only — not for `main` until the user says so.

## Goal

Chat replies can carry an interactive **view** (weather card, place list, trip, comparison table, steps…) generated by the model in OpenUI Lang and rendered with our own notch-styled components. The text answer stays in the chat (and is read aloud); the view opens full in the notch.

**2026-11-15 pivot (user):** the separate Canvas tab is gone. Views live inside Chat: the reply's text in the chat, the view as a compact card under it that opens it full. Chat history therefore keeps every view. The model prefers a view in most replies and skips it when a sentence covers the answer.

## Library choice

[OpenUI](https://github.com/thesysdev/openui) by Thesys (MIT). We use only **`@openuidev/react-lang`** (parser + prompt generator + streaming `Renderer`, ~225 KB with `lang-core`), pinned to **1.0.2** (oldest 1.x old enough to trust; `lang-core` pinned by `overrides`).

Not used:

- `@openuidev/react-ui` — 16 MB unpacked, pulls d3, Radix, KaTeX, react-markdown. Too heavy for a low-RAM notch, and its look is not ours.
- `@openuidev/react-headless` — wants the Vercel `ai` SDK and its own chat state; the host already owns the conversation.

Privacy checks done before installing:

- `lang-core` has a **postinstall** script that sends install telemetry to PostHog. Bun does not run dependency lifecycle scripts (not in `trustedDependencies`), so it never runs.
- Runtime telemetry (system-prompt generation, parser parse) is **opt-in** (`OPENUI_RUNTIME_TELEMETRY_ENABLED`) and in a browser there is no `process.env` to opt in with. Off.
- In dev builds `react-lang` auto-mounts its devtools widget into the page. `canvas/devtoolsOff.ts` sets the library's own opt-out flag before the library is imported.

## Shape

```
Notch (React, agent-notch webview)                  Host (Rust)
──────────────────────────────────                  ───────────
canvas/library.tsx  ── createLibrary(components)
        │  library.prompt(...)  = component reference
        ▼
AgentPanel  ── commands.agentRun(messages, context, generation, record, uiSpec) ──►  agent_run
        ▲                                                   ├ build_messages (+ the latest view sent back)
        │                                                   ├ UI_RULE + spec + UI_FORMAT_RULE as a system msg
        │                                                   ├ run_with_tools (same tools/providers)
        │                                                   ├ split_ui: text  |  "root = …" program
        │                                                   ├ speak the text (never compact when a view came)
        └──── AgentReply { text, ui } ◄─────────────────────┴ record { text, ui } in the chat
chat bubble: text + view card  →  AgentCanvas (full view, fitted shell)
```

- **One conversation**: views are part of the chat history (`AgentHistoryMessage.ui`). Only the latest view is sent back to the model, so a follow-up can refine it without resending every old view.
- **The frontend owns the component library**, so the prompt describing it is generated from the same definitions that render it. It goes to the host as `uiSpec` (≤ 96 KB).
- **A new view opens on its own** (first reply or follow-up). "‹ Chat" (or Escape) goes back; the card reopens it. A follow-up without a view returns to the chat.
- **Interactions**: view buttons send the next chat message; `open_url` goes through the host link opener; forms send their field values along. The open view has its own composer for typed follow-ups.
- **Fallback**: a reply with no `root =` line is a normal chat reply.
- **Speech mode**: a reply with a view always opens the notch, even with `agent_compact_voice` on (the text is still spoken).
- **Lifetime**: the renderer is mounted only while a view is open.

## Sizing

Live window resizes are off the table (WebView2 re-present blink; tauri#3990 freeze). The notch opens at a fixed reply size and clips the window with a region to the shell (`agent_notch_shape`).

- The reply window is **760×620** CSS px (`NOTCH_REPLY`): the view maximum plus clip slack.
- **Chat and the chat list stay 600×360.**
- **A view** measures its content and asks for `clamp(360, w, 720) × clamp(150, h, 600)`. Designed views are 440 px wide.
- **No scrolling, ever** (user): the prompt states the space (~440×480, tables up to 680 wide) and per-block limits (Places 5, List 5, Table 6×5, Steps 6, Details 6, Buttons 3), components cap themselves at those limits, and a view still taller than the max is scaled down to fit.
- Clip rules unchanged: widen before growing, tighten only after the shell has settled.

Windows-only clip (as today).

## Components

Designed views carry the look; the model only fills in data: `Weather` (+ `Hour` columns, temperature curve), `Places` (+ `Place` rows with photo thumbnails and status), `Journey` (flight/train/bus/drive with progress and facts), `Hero` (one big number). Building blocks for anything else: `Canvas` (root), `Stack`, `Card`, `Heading`, `Text`, `Markdown`, `Badge`, `Icon`, `Image`, `Stat`, `Progress`, `Divider`, `Details`/`Pair`, `Table`, `Steps`, `List`/`ListItem`, `Buttons`/`Button`, `Form`/`Input`/`Select`. No maps: real map tiles need a map library and network tiles; a place list with "Open in Maps" links (`open_url`) covers the example for now.

### Look (2026-11-15, user picked "Calm Apple-style" from chat mockups)

v1 was monochrome and bleak; v2 let the model pick loud tones per reply (shell wash, gradient cards) and read as "AI-generated". v3 is calm: near-black, three greys of ink, hairlines, quiet pills, large light numerals. Colour only carries meaning and is mostly chosen by the components, not the model: weather glyphs colour themselves, status tones (good/warn/bad/muted) for real status, trend green/red. Designed views are a fixed 440 px wide so replies look consistent.

### Images

`Image`, `Place` and `ListItem` thumbnails. https only, `no-referrer`. A missing or broken photo never shifts the layout: rows show an icon tile (`Place` icon, default map-pin) and `Image` shows a quiet placeholder of the same shape. The prompt allows only image URLs that came back from tool results (the web extension). Loading a remote image tells that host the user's IP — inherent to showing web images.

### Voice line

With a view, the reply's text is one or two short, warm sentences that give the answer ("It's 14 degrees with light rain until 3, then it clears up."), never a description of the view. It is shown in the chat and spoken through normal talk-back. The host splits the program off (`split_ui`).
